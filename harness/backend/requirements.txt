# What the application needs at runtime in every configuration it ships in.
#
# ``scripts/package.py`` compares this file against the build environment before it
# freezes anything, and stops the build when a declared distribution is missing. The
# reason is that PyInstaller collects what is *installed*, not what is declared: a
# freeze run from an environment without a dependency produces a bundle whose feature
# fails on a tester's machine with no build-time signal at all. That is exactly how a
# shipped build came to carry a document-upload path whose multipart parser was never
# frozen, and a text-to-speech tool that could only ever refuse.
#
# Requirements that only one deployment configuration needs, or that back a capability
# the desktop bundle deliberately does not carry, live in ``requirements-optional.txt``.
# Tests need ``requirements-dev.txt``.

# Live web search. The package was renamed from duckduckgo-search to ddgs; the
# 8.1.1 duckduckgo-search line is a rename stub whose backend returns nothing,
# so pinning it made web_search succeed and report zero results. app/harness/
# ddg_provider.py still accepts the legacy module name for environments that
# have not migrated. It also prefers a headless-Chromium provider when
# playwright is installed (HARNESS_CHROMIUM_SEARCH=1, default on), so a network
# that refuses DuckDuckGo's HTML endpoint still gets real results; ddgs remains
# the fallback for the frozen desktop bundle, which excludes playwright.
ddgs==9.16.0
# Bumped from 0.0.22 by the shipping audit: five advisories in 0.0.22, fixed across
# 0.0.26-0.0.31. This parser is on the document-upload path, so the advisories are
# reachable by any authenticated learner.
python-multipart==0.0.31
# Pinned, not ranged. ``app/course_builder.py`` imports ``PdfReader`` lazily, so a range
# here is invisible at import time and only bites when a learner uploads a PDF: a new
# pypdf minor could change the text-extraction output the builder's glyph repair is
# written against. It also broke the release gate -- ``pip-audit -r requirements.txt``
# refuses a requirement that is not pinned to an exact version, so the declared
# vulnerability scan could not run at all.
# 6.19.0 was the version the suite was green on; the audit's scan then reported advisories
# against it with fixes through 6.21.4, so the pin moved to the fixed line.
pypdf==6.21.4
