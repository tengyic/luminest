# Luminfest — end-to-end repair and content-autonomy brief

You are working on Luminfest: a native macOS learning harness (SwiftUI client, FastAPI
backend, 102 endpoints, 51 agent tools, 37 tables, 1518 tests). Every subsystem is
implemented and the test suite passes. **It still does not teach anyone.** Your job is to
make a stranger able to sit down, name a topic, and be taught — then to remove the
developer-authored content that currently props the demo up.

Read this whole brief before touching anything. It is designed so you do not have to
explore the repository to understand it.

## 2. The reported failure

A user logged in with a normal account. The course did not start. They typed questions and
got no response.

---

## 3. Verified root cause — start here, do not re-derive

**There is no answer channel.** A learner's response is never captured anywhere.

| Evidence | Location |
|---|---|
| `check_understanding` serves a question and records nothing. Its own note reads "Answers and diagnoses stay server-side until the attempt is scored" — nothing scores. | `backend/app/harness/toolbox.py:617` |
| `AdvanceInput` = `order`, `outcome ∈ {done, skipped}`, `seconds`, `note`. **No answer field.** | `backend/app/routes_procedure.py:137` |
| The client advances with `outcome: "done"` — the block completes without the choice. | `native/Sources/LearningHarness/LessonProcedure.swift:396` |
| No endpoint among 102 accepts an answer; no tool among 51 records one. | verified 2026-11-04 |

Consequence chain, which explains both symptoms:

1. No attempt row is written.
2. `learning_states` never moves off `PRIOR` 0.15 ("no attempts yet").
3. No diagnosis can fire — not concept, not calculation, not procedure.
4. Adaptation, FSRS scheduling, IRT/KST, and the memory curve all starve for input.
5. The lesson degrades to a slideshow. In chat, a procedure block cannot be advanced at
   all, which is the "no response" the user saw.

**Second, independent cause of thin content.** `_require_teacher`
(`backend/app/harness/toolbox.py:855`) refuses every asset-creation tool for a learner
role, and `_ensure_operator` promotes only the oldest account. A freshly registered user is
a learner, so the harness *declines to generate* and the UI looks content-starved. Confirm
this before concluding the content is missing.

Fix these two before building anything new. A feature added on top of a broken answer
channel will also appear broken.

## 4. Definition of done — an observable run, not a test count

The suite passing is not evidence. Produce a scripted first-person run and attach its
output. It must use a fresh database and a brand-new account, with no seeded courses and no
operator promotion:

1. Start the backend on a fresh DB. Register (needs `age_confirmed` **and** `accept_terms`,
   else 422).
2. Ask for a course on a topic **not in `curriculum.py`** — pick something the repo has
   never seen.
3. Confirm: a syllabus is produced; a procedure run starts; the first block renders; a deck
   is materialised; the tutor speaks.
4. Answer a question. Confirm an attempt row exists and `learning_states` moved.
5. Confirm the diagnosis is specific (concept / calculation / procedure), not generic.
6. Confirm the next block changed because of that answer.
7. Repeat until the lesson ends. Confirm a summary and the next scheduled review.

Each step needs a pass criterion you can observe (status code, row count, rendered text).
A step that "seems fine" is a fail.

## 5. Content autonomy — the real bar

The complaint is that a lot of the current material was authored by the developers, not
generated by the harness. Every artifact below must be produced **at request time, from a
topic the learner names**, and must be good enough that a teacher would use it.

| Artifact | Existing tool | Bar |
|---|---|---|
| Multimodal images | `image_generate`, `find_image`, `image_search` | Relevant, correctly captioned, licence-clear, embedded in the lesson |
| Video | `find_video`, `search_videos` | Verified embeddable; a video that cannot be verified is a link, never an assumption |
| Slides | `generate_slides`, `build_presentation`, `deck_control` | Real typography and layout — headings, hierarchy, readable type. Not bullet soup |
| Flashcards | `compose_content(kind='cards')` | Grounded in the actual source, scheduled by FSRS-6 |
| Simulations | `write_simulation`, `edit_simulation`, `check_simulation` | Validated **and** checked at runtime; a non-finite number in visible text is a failure |
| Speech | `text_to_speech` (local VoiceStudio) | Fluent; interruption-aware; degrades to text with a stated reason |
| Whiteboard | `whiteboard_*`, `board_*`, `illustrate_course` | Draw, place images, label with text boxes, rotate/scale — while speaking |
| Course design | `author_course`, `draft_course`, `extend_course` | NotebookLM-like: take the learner's goal, search real sources, design a syllabus, then generate |

**Hard rule: no dev-authored shortcut.** If a course can only be taught because
`curriculum.py` holds hand-written lessons for ~30 of 164 graph nodes, that is the defect,
not the safety net. Generated content must be at least as good as what is there now.

**Absence is designed.** A missing provider degrades to a declared fallback with a reason.
It never raises, and it never fakes output. Do not "fix" a missing capability by inventing
a plausible artifact.

## 6. Gaps from the product brief still open

Details and file pointers in `context/04-open-gaps.md`.

1. **Unit projects** — absent. The brief wants a small project after each unit: a
   presentation delivered on camera with speaking, or a research task with limited AI use.
   There is no student artifact today: no capture, no submission, no rubric.
2. **Multi-perspective analytics** — `collaboration`, `creativity`, `soft skills` have zero
   implementation. Participation, struggle, attention and streak exist. These are rubric
   fields over data already logged; collaboration additionally has no product surface.
3. **Formally graded unit tests** — graded items exist, but there is no unit-level grade
   book judged against academic standards.
4. **Teacher clone** — transcript-only. The brief wanted video CV, facial expression, body
   language, voice tone. It was called a bonus; do it last or not at all.

## 7. Invariants — violating these still runs, and quietly harms learners

- **Decision layers never collapse**: `teaching/policy` (what to teach) · `session`
  (phase/turn) · `procedure` (activities) · `supervision` (should we interrupt) ·
  `classroom` (state machine). `classroom` imports supervision's primitives.
- **`mastery_known` is not `mastery`.** `PRIOR` 0.15 means "no attempts yet"; only the
  route sets the flag.
- **Never punish.** Away is not guilt. Suspicion (too fast, original-not-variant, cannot say
  why) routes to a variant question or an explain-back — never to a detector or a ban.
- **A plan is a promise.** Store the compiled plan; only *existing* artifacts may be
  promised, and a missing one becomes `skipped`. A plan that reshapes mid-session is not a
  lesson.
- **Evidence over vibes.** Every adaptation must cite what it adapted on. The entertain-vs-
  progress tradeoff is real: engagement that does not move mastery is a failure, not a win.

## 8. Environment traps that will waste your time

- `grep "a\|b"` silently matches nothing here (toybox grep, no BRE alternation). Use
  `grep -E`. An empty result is not evidence until the query is proven to work.
- Tests need cwd `backend/` and a `TMPDIR`/`--basetemp` inside the repo.
- `swift build` needs `--disable-sandbox`. Never use `Bundle.module`; use `AppResources.url`.
- `check_simulation` reports `checked=False` in the packaged app (no Playwright in the
  bundle). That means unverified, not broken — the tool says so.
