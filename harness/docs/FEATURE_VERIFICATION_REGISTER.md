## Purpose

One register for the whole application: what the learner sees, where it is implemented natively, where it is implemented on the server, what it persists, what proves it, and the measurable condition that makes it done.

## Definition of done

A feature is verified only when all six elements are present and the cited test path exists: user-facing functionality, native implementation, backend implementation, data model, automated tests, and a measurable acceptance criterion. `partial` and `absent` rows are findings, not claims of completion.

## Boundaries

- **Database Security:** A parallel agent owns database/tenant security hardening. This register records the current expected path and the existing security tests, but makes no change to security code and does not claim that hardening is complete.
- **Rule:** A row is only 'implemented' when all six elements are present and the cited test path exists. 'Partial' means the user-facing path exists but a listed element is incomplete. 'Absent' is a finding, not a TODO.

## Status legend

- **implemented** — User path, native path, backend path, data path and an automated test exist.
- **partial** — The feature runs, but one or more of the six elements is incomplete (for example no native surface, or no direct test).
- **absent** — No implementation exists; the register names the gap so it cannot be mistaken for done.
- **external** — Owned by another agent or outside this program; recorded for completeness, not claimed as verified here.

## 1. Authentication and onboarding

### AUTH-01 · Account registration and launch gate

**Status:** `implemented`

- **User-facing functionality:** Create an account with name, email and password; the launch gate requires the 13+ confirmation and acceptance of the Terms and Privacy Policy.
- **Native implementation:** native/Sources/LearningHarness/LuminfestApp.swift — OnboardingView, register/sign-in segmented control, age and terms toggles.
- **Backend implementation:** backend/app/main.py POST /api/v1/auth/register; backend/app/accounts.py; backend/app/security.py (Argon2 hashing, session issue).

- **Acceptance criteria:** Access token TTL is 3600 s; refresh rotates and the old refresh token is rejected; logout revokes the session; a revoked token gets 401.

## Maintaining this register

1. Add or edit a feature in `docs/feature_verification_register.json`.
2. Every feature must carry all six keys; the validator refuses an incomplete row.
3. Run `python scripts/verify_feature_register.py` to validate and regenerate this file.
4. Run it with `--check` in CI if the register must not drift.
